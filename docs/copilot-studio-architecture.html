Single-user pilot · current setup

Lark ↔ Copilot Studio bridge

You chat with a Lark bot. A published Microsoft Copilot Studio agent does the thinking. When it needs Lark data, it asks the bridge on the owner's laptop to run lark-cli with the owner's own Lark login.

Architecture

Blue Lark traffic Purple Microsoft traffic Orange tool calls through the tunnel Dashed in-process

The four connections

A Bridge ⇄ Lark

An outbound WebSocket from the laptop. It uses the bot app's App ID and secret. No inbound port is needed.

B Bridge → Copilot Studio

Outbound HTTPS to Direct Line. The Studio "web channel security" secret is exchanged for a 30-minute conversation token.

C Copilot Studio → laptop

The only inbound connection, so it's the only reason for the tunnel. It carries MCP tool calls and needs the MCP API key plus a per-message execution token.

D lark-cli → Lark API

Outbound HTTPS using the owner's personal Lark login for this profile.

One message, start to finish

  1. 1
    Owner sends a DMe.g. "What's on my calendar today?" Lark pushes it to the bridge over connection A.
  2. 2
    Access checkOnly the bot's owner in a private chat gets through. Groups, other people, doc comments and meetings are refused before anything reaches Microsoft.
  3. 3
    Wrap and signThe bridge adds Lark context (chat, sender, bot name) and mints a random execution token that works only for this one message.
  4. 4
    Send to Copilot StudioThe message is posted into the owner's Direct Line conversation (connection B). Follow-ups reuse it, and /new starts a fresh one.
  5. 5
    The agent decidesThe model reads its Instructions and chooses a tool, e.g. run_lark_cli ["calendar","+agenda"] with the execution token.
  6. 6
    Tool call reaches the laptopThrough the ngrok URL (connection C). The MCP server checks the API key, then the token, then the command rules. High-risk commands wait for the owner's /approve in Lark.
  7. 7
    lark-cli runsIt runs directly, with no shell, a minimal environment and the owner's login, and calls the Lark API (connection D). The JSON result goes back to Studio.
  8. 8
    The agent answersThe model writes the reply, and Studio sends a turn.complete signal.
  9. 9
    Reply in LarkThe bridge collects the reply, revokes the token so any late tool call is refused, and posts the answer in the DM. Typical time: 5–10 s, or a minute or more for multi-step tasks.

Checks on every tool call

✓ Right caller

The request must carry the MCP API key. Browser requests and any path other than /mcp and /healthz are refused.

✓ Right message

The execution token must be live and belong to the message being answered. It's revoked on completion, stop or timeout.

✓ Allowed command

Read-only mode allows 9 read commands. Full mode allows all lark-cli commands except auth, config, profile, update and api, identity switching, --jq and paths outside the working folder.

✓ Owner approval

Deletes, permission changes and anything lark-cli marks high-risk wait for /approve <code> from the owner in Lark. Nothing runs twice if Studio retries.

Who sees what

WhereWhat's there
LarkThe owner's messages and the bot's replies.
Microsoft (Copilot Studio)Each message the bridge sends (text, Lark context, execution token), every tool result (the owner's Lark data) and the replies. It's kept in the agent's conversation transcripts.
ngrokAll tool traffic: the API key, commands and returned Lark data.
Owner's laptopEncrypted secrets, the owner's lark-cli login, and logs (events, timings, a short preview of incoming messages).

Lifecycle

  • Start: decrypt secrets, check the lark-cli login, open the MCP listener on port 47821, connect to Lark.
  • Running: one message at a time. Stop, /new and timeouts cancel the turn and revoke its token.
  • Stop: all tokens are revoked and the listener closes, so Studio's tool calls fail until the bot is back.
  • Restart: the next message starts a new Copilot Studio conversation, and the bot says so.

Limits of this setup

Single user. Every command runs with the owner's Lark login, so only the owner can use the bot. Colleagues are refused by design.

Laptop-bound. It works only while the owner's laptop, the bridge and ngrok are all running.

Cloud data flow. Lark data returned by tools is sent to Copilot Studio in Microsoft's cloud, and passes through ngrok.
